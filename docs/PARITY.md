# Dolphin parity checklist

Status: ✅ done (implemented **and** tested), 🟡 partial (what's missing or untested is noted), ❌ missing.
Reference: Dolphin (KF6) handbook. This file is updated at the end of every milestone.

"Tested" here means exercised in the real app through its actions (scripted with `TUCK_ACTIONS`, checked in screenshots) or by unit tests. GTK4 has no public API for synthesizing key presses, so behaviour that only runs on physical key or mouse input is marked 🟡 until it's checked by hand.

_Last updated: Milestone 8 (panels, tags, git, service menus, places, selection mode, shortcuts, redo, columns)._

The test hooks can now also select items, type into dialogs, answer dialogs, open context menus and simulate drops (`select:`, `type:`, `respond:`, `menu`, `drop-copy:` …), type into the terminal panel (`term:`), print an action's keys (`accels:`) and open a Preferences page (`prefs:`); see `crates/tuck/src/debug.rs`.

| Duplicate (Ctrl+D) | ✅ | "Report copy.pdf", "Report copy 2.pdf", for files and folders |
| Move to Trash / Restore | ✅ | Own freedesktop Trash implementation (home trash and per-drive `.Trash-$uid`), checked against GNOME: `gio list trash:///` shows Tuck-trashed items with their original path, and Restore from Tuck's Trash view works. Restore never overwrites and recreates missing folders. Undo toast. Drives without a trash offer permanent deletion instead. |
| Permanent delete (Shift+Del) with confirmation | ✅ | Confirmation names the items and says it can't be undone; Cancel is the default. Empty Trash is confirmed too. |

Every kind is unit-tested through two full undo/redo cycles; trash → undo → redo is tested in the app. A new action clears the redo list. History lasts for the session. |
| Background jobs with progress and cancel | ✅ | Jobs run on worker threads. The header shows a spinner and a popover with progress bar, bytes and items, and Cancel. Each top-level item is all-or-nothing: cancel or failure removes what it created, and a move deletes the source only after a complete copy. Files are written under a hidden temporary name and renamed into place. A free-space check runs before starting. Closing the window asks, cancels and cleans up. After a crash or `kill -9`, leftovers are swept on the next start (tested). |
| Conflict handling: replace / skip / keep both / apply to all | ✅ | Dialog shows size and date of both versions. Folder onto folder offers Merge and asks per clashing file inside. "Apply to all" is remembered separately for files and folders. Replace swaps atomically. |
| Create New: folder, file, from templates | 🟡 | New Folder tested. New Document (empty file, or any file in `~/Templates`) is implemented but untested. |

| Tags (xattr `user.xdg.tags`, Baloo-compatible) | ✅ | Information panel: tag chips with remove buttons, and an entry to add tags. Stored exactly as Dolphin/Baloo store them (comma-separated). Read/write is unit-tested on ext4; the info panel, sidebar and tag search are tested in the app. Tags can be edited for one item at a time. | Comments (`user.xdg.comment`) and rating | ✅ | Information panel: five-star rating (stored as Baloo's 0–10 `user.baloo.rating`; click the current star to clear) and a comment field saved on Enter or when focus leaves. Unit-tested; shown in the app with values written by another tool. |
| Git status indicators | 🟡 | Coloured dots in all three views for modified, added, renamed, deleted, conflicted and untracked items; folders show the strongest state inside them. | Search (names + contents, filters) | ✅ | Ctrl+F or the search button. Results show in the current pane as you type, best match first: exact name, then prefix, then word start, then anywhere, adjusted for depth, recency and hidden items. Details shows a "Where" column. Filters: kind, date, size (drop-downs or typed `kind:pdf`, `modified:week`, `size:>10mb`), `tag:` (Dolphin-compatible `user.xdg.tags`), `in:` path, `hidden:yes`. Scope: This Folder or Everywhere. "Contents" also searches inside text and source files. All tested in the app. |
| Search index | ✅ | Persistent name index of the home folder, loaded at startup in ~75 ms, then refreshed on an idle-priority thread every 5 minutes and soon after any change made in Tuck. Refreshes re-read only changed folders (0.08 s for 416k entries). Skips the contents of `.git`, `node_modules`, caches and anything with `CACHEDIR.TAG`; doesn't cross into other drives. Under 50 ms on 1M entries even on 2 threads (see `docs/BENCHMARKS.md`). |
| Live search fallback | ✅ | Folders outside the index (other drives, system folders), or before the first index is ready, are searched by a parallel walk that streams results in batches (tested on `/usr/share/doc`: 2,810 results in 0.1 s) |
| Content index | 🟡 | tantivy full-text index of text and source files ≤ 1 MB, incremental by modification time, deletions dropped (unit-tested). Not benchmarked on a large real home folder. PDFs and office documents aren't content-indexed yet. |
| Live folder updates | ✅ | Create, delete and rename from outside the app appear immediately |
| Keyboard-only operation | 🟡 | Every action has a shortcut or a menu entry; the Menu key and Shift+F10 open the context menu. Not yet verified with keyboard only. |
| Customizable shortcuts | 🟡 | Preferences › Keyboard lists every shortcut by group. Click one and press new keys; Backspace removes it, Esc cancels. If the keys are taken, it names the other action and asks you to press again to move them. Per-row Reset and Reset All. Saved in `settings.json` and applied at once, for both window and file-view shortcuts. A saved override is tested to bind in the app; key capture needs real key presses and is untested. |
